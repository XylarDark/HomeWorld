### Harness traps (2026-09-30, HR4-B)

- **`git checkout <branch>` clobbered `Docs/README.md` (case collision, Windows):** two tracked paths differing only in case (`Docs/README.md` + `docs/README.md`) resolve to **one file** on a case-insensitive volume, so checking out the branch that has **both** silently overwrote the 74-line canon README with the 37-line engineering one; git then refused the follow-up merge with *"local changes would be overwritten"*. **Avoid:** land by **ref push** (`git push origin <sha>:refs/heads/main`), never `checkout main` + `merge`; verify with a throwaway `git worktree add --detach <dir> main` and a case-fold collision scan of `git ls-tree -r --name-only`. **Root fix landed** — `Docs/README.md` (canon) and `docs/README_ENGINEERING.md` (engineering) are now distinct names; the collision no longer exists on `main`.
- **Adapter must not manufacture findings (SkillEvaluator ⇄ `.mdc`):** materializing a Cursor rule into an Agent Skill and dropping `version` from frontmatter made the real scorer deduct 5 correctness points **against all 31 rules** for an omission made by the *adapter*, not by the rules — mean looked like 85.6 instead of 87.3, and two rules looked below threshold instead of one. **Avoid:** pass through every field the scorer reads; where the target format has no equivalent (`.mdc` has no `metadata.author`/`tags`), **declare the constant offset rather than fabricate data** — `score-mdc-rules.js` records `formatOffsetComposite: 3.5`. Fail loud (`exit 2`) when the scorer is missing; never report an unscored rule as passing.
- **`similarity-check --type rules` cannot see a Cursor rule corpus — it keys on `title`, Cursor writes `name`:** `skillevaluator similarity-check .cursor/rules --type rules` exits 1 with `No rules content found to compare` and `files_scanned: 0`, because `embedding/extractor.py:_discover_rules` reads the rule name from a **`title`** frontmatter field and **0 of 31** rules in `.cursor/rules/` have one — they all use `name:`, exactly as Cursor writes them. **Avoid:** do not read that error as "the folder is empty" or "the tool is broken"; materialize the rules into Agent Skills first (the skill discovery path reads `name:`) and run `--type skill`. Note also that `--save-catalog` **rejects non-skill content** (`Local catalog workflows support skill content only`), so a rules catalog is only reachable through materialization. Same schema shape as the Tier 1 `.mdc` ⇄ `SKILL.md` gap above.
- **`UserHarness/scripts/tools/rename_devharness.py` is a one-shot mutator at a machine-absolute path:** rewrites the submodule against **`c:\dev\HomeWorld\DevEnvTemplate`**, a path that no longer exists after the P5 rename. **Avoid:** **never run it** — the rename is complete and recorded in `Config/userharness-pin.json` (`renamedFrom: DevEnvTemplate`); if a rename is ever genuinely needed, write a new idempotent script instead of reviving this one.
- **LLM judging is not a measurement on one run (Skill Lift):** the same `19-automation-cycle.mdc` has scored **5.0 / 40.5** in one full pass and **57.7 / 58.6 / 60.5** in an earlier one — same judge, identical bytes. Corpus-wide the **pooled within-rule SD is 8.13** with **max spread 35.5**, so this is not one bad rule. `quality-check` is deterministic and gives identical output every run; `rubric-eval` is a sampled verdict and does not. **Avoid:** never report a single `rubric-eval` run as a rule's score, and never treat a **sub-8-point** delta as a regression; `scripts/score-mdc-lift.js` takes `--repeat N` and records `meanSpread`/`maxSpread` in the report, and prints *"a single run is not a measurement"*. Always record the **judge model** (`nvidia/nemotron-3-super-120b-a12b` today) alongside the score — a verdict from a different judge is a different measurement, exactly as a different scorer version is.
- **Structural score and judged score are not the same measurement:** `quality-check` (mean **87.4**, deterministic, no LLM) and `rubric-eval` (mean **62.3** over 29 of 31, sampled) answer different questions and their numbers **must not be averaged or diffed** — the gap between them is not "deficit", it is arXiv 2608.20614's ρ = 0.14 made concrete. `score-mdc-lift.js` sets `comparability.againstQualityCheck: false` in every report so a future consumer cannot quietly merge them.
- **Scorer substitution is fail-open (SkillEvaluator harness):** `resolveTool` fell through from an explicit `--tool` to a bare PATH lookup, so asking for scorer X could silently run scorer Y while the report named X — one rubric's numbers attributed to another. Separately, `toolVersion(tool)` ran *before* the not-found guard, turning a clean `exit 2` refusal into an `ERR_INVALID_ARG_TYPE` stack trace and `exit 1`. **Avoid:** an explicit `--tool` is authoritative and is **never substituted**; probe the version only after the null check; a missing scorer must produce a **message**, never a stack trace.
- **Unanchored scores are not reproducible:** a `[tier3]` reinstall silently moved SkillEvaluator **0.3.0 → 0.4.0**. ### task-lift pilot: 8 agent runs rejected, but the report still showed a +25pp lift

### PowerShell: `Add-Content -Encoding UTF8` corrupted an append-only file
- **Error:** Appending a section to `docs/SESSION_SUMMARY.md`, an append-only record, with `Add-Content -Encoding UTF8` rewrote a pre-existing section sign (`0xA7`) as U+FFFD (`EF BF BD`) about 84 KB into the file, and injected 6 CRLF terminators into an otherwise pure-LF file. ### `docs/SESSION_SUMMARY.md` is not valid UTF-8: one cp1252 byte at 84213
- **Error:** `pathlib.read_text(encoding="utf-8")` raises `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xa7 in position 84213`. That byte is SECTION SIGN, sitting in the line `Docs/CANON_MAP.md §3 is the cross-link`. Everything around it is clean UTF-8, so the file is UTF-8 with a single cp1252 character pasted into it.
- **Why it matters:** anything reading this file with a strict UTF-8 decoder fails outright, and the file is the append-only session record, so it is read on nearly every hand-off. Reading it with `errors="replace"` yields exactly one U+FFFD - a replace-based reader silently corrupts one character and still looks healthy.
- **Confirmed (2026-10-04):** `raw.decode("utf-8")` fails at 84213; `utf-8` with `errors="replace"` gives exactly 1 replacement character; `cp1252` fails too, at a *different* offset (13236), so the file is not cp1252 throughout. `latin-1` decodes clean, but that is true of any byte string and proves nothing here.

### `max(a, b)` decides by position, so a NaN in the second argument is discarded
- **Error:** `env.ue_island_measured` computed `worst = max(off_x, off_y)` and then tested `worst <= tol`. With `off_y = NaN`, `max` returns `off_x`, because `max` returns its first argument whenever the second is not strictly greater — and `NaN > x` is always `False`. The row reported **PASS** while its own note read `off by 0.00 m in X and nan m in Y`. NaN in the *first* slot failed correctly, so the bug depended on argument order.
- **Why it was reachable:** `json` accepts the bare literal `NaN`, so a committed measurement record can carry one. It was not hypothetical.
- **Fix / rule:** never let an aggregate decide a verdict. Guard the inputs (`math.isfinite` on every value before comparing) *and* write the comparison out — `off_x <= tol_x and off_y <= tol_y and off_z <= tol_z`. Either alone would have caught this; the reason to do both is that the guard gives a readable message and the explicit form cannot be silently reordered. This is the same family as the "absence of evidence read as evidence" entries above: a comparison that never ran looks exactly like one that passed.
- **Also found in the same check:** the tolerance was derived from the X span alone and applied to both axes, making the 100 m Y axis 3.6% rather than the documented 2%; and Z was read from the source report but never compared, so a 180 x 100 x 0.05 plate passed a row written for 180 x 100 x 0.45.
- **Context:** 2026-10-04, found by an adversarial review of code written about an hour earlier. Six such holes were found in that review; all six are closed and each has a test that fails if the hole is reopened (`TheExportChainCannotGoStale`).

### Comparing an object-space box to a world-space AABB is wrong by construction, not by tolerance
- **Error:** the in-editor measurement script recorded `actor.get_actor_bounds(False)` — a **world-space** axis-aligned box — and the gate compared it against `measurements.SM_IslandTop.bbox` in the greybox report, which is `max(xs) - min(xs)` over the object's own vertices, i.e. **object-space**. Any rotation of the island actor makes the world box strictly larger than the object box, so the check would have reported FAIL on a correctly placed island.

### An unsourced number is an invention wearing a number's clothes
- **Error:** `feel.tunable_baselines` accepted *any* non-null scalar in `Docs/qa/POLISH_BASELINE.json` as a measurement. The file's own `_waiver_policy` already said "Do not write a number here to make a gate go green. A null that is honestly null is worth more than a plausible value, because a plausible value cannot be told apart from a real one later" - and the gate could not tell them apart. Filling the block with six bare numbers turned a RED row green.
- **The subtler half, and the reason the first fix did not hold.** The replacement helper returned `(value, reason)` and the caller tested `if got is None:`. A two-tuple is never `None`, so **every rejected entry counted as measured** - and `test_all_null_tunables_are_not_a_baseline`, the test written specifically to stop a seeded skeleton going green, **passed on it**. `null` was being recorded as a value. The guard existed, was named correctly, and never fired. A sentinel you never compare against is a missing check wearing a check's clothes.
- **Why this class is easy to miss:** a green test suite is the evidence, and here the suite was green *because* the defect was present. Mutation testing is the only thing that caught it, and it caught it by reverting the one line that made it true.
- **The rule, now enforced:** a baseline is a record `{value, source, confidence}`, never a bare scalar. A source is required and must be non-blank. A placeholder (`tbd`, `unknown`, `n/a`, `none`, `todo`, `-`, `?`) is rejected however well it is sourced. A **string is a legitimate value** - "no such parameter in the build" is more decisive than a number, and two of the six FEEL.md proposals aim at knobs that never existed - but the tally must separate numeric from absent, or `6/6` reads as six numbers when two are absences.
- **Second rule from the same session: a BEFORE value must not be a proposed-range bound.** `night_length_s` was recorded at 120.0, which sits inside FEEL.md's proposed 90-180 s window. That is legitimate - it is what the code says - but a baseline that lands exactly on a bound is indistinguishable from someone copying the proposal and picking the middle. The test names the possibility instead of pretending it is absent.
- **Measured, 2026-10-04, and worth keeping because it changed the work:** of six FEEL.md tunables, **two have no corresponding parameter in the build**. `glide_gravity_scale` - FALLBACK glide is spline interpolation over `CRUMB_GlideSpline` with a duration (`GlideDurationSeconds = 32.0f`, clamped 25-40), never a physics arc, so a 0.35-0.55x-gravity proposal has nothing to scale until someone adds a property. `camera_pitch_bias_deg` - no bias parameter exists; pitch follows controller rotation through the spring arm. A third, `gather_cooldown_s`, is **already half-decided in code**: `HarvestCooldownSeconds = 0.f` with `bDepleteUntilDawn = true`, i.e. the build chose the deplete-until-dawn branch of a proposal that offers "until dawn **or** 60-120 s", leaving only whether dawn-depletion stays as an open question.
- **Confidence is recorded per entry, and the gradations are not decoration.** `high` = C++ or CVar default, no `.ini` override, no override found in any `.uasset` name table. `medium` = read a component, not every input path reaching it. `low` = absence of an *identifier*, which is weaker evidence than absence of a parameter actually read. `glide_lateral_influence = 0` is `medium`: the glide component never binds input, which matches canon "FALLBACK = no free steer", but that is a claim about one component.
- **General form:** a guard that is never exercised by the code it guards is indistinguishable from a guard that does not exist. When a helper returns a sentinel, compare against it in the same commit that writes it - and prove the comparison fires by reverting it.
